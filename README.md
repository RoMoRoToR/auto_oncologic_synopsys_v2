# Synopsis.Assist — Bioequivalence Planning

Инструмент для автоматического планирования исследований биоэквивалентности (БЭ): выбор дизайна, расчёт выборки, определение таймпоинтов, формирование статистического плана и генерация структурированного синопсиса с артефактами (DOCX / PDF / JSON / MD / YAML).

Решение ориентировано на автоматизацию подготовки черновика протокола БЭ на основе регуляторных требований, данных референсного препарата и фармакокинетических параметров.

---

## Соответствие требованиям кейса

Система реализует следующие блоки:

1. Поиск и анализ литературы
   Поддерживается работа с открытыми источниками и реестрами:

   * PubMed — PK-профили, CVintra, дизайн ранее проведённых исследований
   * DrugBank — сводная информация по препарату
   * GRLS (ГРЛС РФ) — реестр лекарственных средств
   * Certara Simcyp — источник данных для PK-моделирования

2. Генерация синопсиса исследования
   Автоматически формируется структурированный документ, включающий:

   * обоснование выбора дизайна;
   * цели и задачи исследования;
   * описание популяции;
   * критерии включения/исключения;
   * дизайн (периоды, рандомизация, фазы, смывы);
   * биоаналитические методы;
   * временную сетку (таймпоинты);
   * PK-параметры и статистическую методологию;
   * расчёт выборки;
   * план мониторинга безопасности;
   * библиографический список.

Документы генерируются в форматах:

* DOCX (черновик протокола),
* PDF,
* Markdown,
* JSON,
* YAML.

## Быстрый запуск через Docker

1. Создайте `.env` в корне проекта по шаблону `.env.example`.
2. Запустите:

```bash
docker compose up --build
```

3. Откройте интерфейс:

```
http://localhost:8000
```

Шаблон DOCX не требуется — документ формируется программно.

---

## Продакшен (сервер)

Рекомендуемый способ — `docker-compose.prod.yml` (app + nginx).

1. Создайте `.env` (можно на основе `.env.prod.example`).
2. Подготовьте данные:

   * `./data/grls.xlsx`
   * `./data/docx/` — папка для артефактов
3. Запуск:

```bash
docker compose -f docker-compose.prod.yml --env-file .env up -d --build
```

4. Интерфейс доступен по адресу:

```
http://<server_ip>/
```

Переменные:

* `WEB_CONCURRENCY` — число воркеров
* `JOB_TIMEOUT_S` — таймаут задачи генерации
* `RAG_TIMEOUT_S` — таймаут обогащения источниками

Если ключи внешних сервисов отсутствуют — система работает в fast-режиме.

## Использование Yandex AI Studio

Система может работать с моделями через Yandex AI Studio.

Для подключения:

1. Создайте ключ в Yandex Cloud.
2. Укажите в `.env`:

```text
YANDEX_FOLDER_ID=...
YANDEX_AUTH_KEY=...
```

3. В конфигурации backend выбирается режим генерации через Yandex LLM.

Yandex AI Studio используется для:

* обогащения обоснования дизайна;
* нормализации структуры документа;

При отсутствии ключей система автоматически переключается в fast-режим.

## Формат входных данных (User Guide)

### Обязательные параметры:

* INN / торговое наименование
* дозировка
* лекарственная форма
* референсный препарат
* необходимость RSABE (да/нет)
* ожидаемый CVintra (если известен)

### Дополнительные параметры:

* предполагаемый дизайн (2×2, replicate и др.)
* целевая мощность
* α-уровень
* предполагаемая разница средних

## Архитектура решения

Система состоит из следующих модулей:

1. API (FastAPI)
   Принимает параметры исследования и управляет пайплайном.

2. RAG-модуль
   Извлекает данные из:

   * GRLS,
   * открытых источников,
   * локальных PDF.

3. Модуль расчёта

   * выбор дизайна;
   * RSABE/ABE логика;
   * расчёт размера выборки;
   * формирование таймпоинтов.

4. LLM-модуль (Yandex / fallback)
   Формирует текстовые разделы.

5. Генератор документов
   Формирует:

   * DOCX,
   * PDF,
   * JSON/YAML.

Поток данных:

Ввод → RAG → Расчёты → LLM-структурирование → Генерация артефактов.

## Формат результата

Система возвращает:

1. Структурированный JSON:

   * дизайн
   * расчёт выборки
   * PK-параметры
   * таймпоинты
   * текст синопсиса

2. DOCX-документ

3. Markdown-версию

Интерпретация:

* размер выборки основан на заданной мощности;
* дизайн выбирается исходя из CVintra и необходимости RSABE;
* доверительные интервалы рассчитываются в лог-пространстве;
* вывод включает пояснение допущений.

---

## Ограничения и допущения

* расчёты основаны на стандартных формулах ABE/RSABE;
* корректность зависит от точности CVintra;
* не заменяет экспертную оценку регуляторного специалиста;
* не учитывает индивидуальные клинические особенности.

---

## Методология валидации

Валидация проводится через:

* сравнение с опубликованными исследованиями БЭ;
* воспроизводимость расчёта выборки;
* проверку корректности доверительных интервалов;
* unit-тесты расчётных модулей;
* интеграционные тесты пайплайна.

Метрики:

* отклонение N от эталонных расчётов;
* корректность CI;
* стабильность генерации документа.

## Сценарии тестирования

1. Стандартный 2×2 cross-over с известным CV.
2. RSABE для высоковариабельного препарата.
3. Отсутствие внешних ключей (fast-режим).
4. Загрузка PDF инструкции.
5. Продакшен-развёртывание с nginx.
